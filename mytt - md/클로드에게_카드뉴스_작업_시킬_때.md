# 클로드에게 카드뉴스 작업 시킬 때 (실전 팁 & 프롬프트 원칙)

> **핵심 요약**  
> 카드뉴스는 깊은 추론이 필요한 작업이 아닙니다. 연구자료 기반이라 "생각 많이 해줘(Thinking)"가 도움될 것 같지만, 실제로는 역효과가 자주 납니다. 생각을 오래 할수록 카피가 설명조로 길어지고, 인스타에서 안 읽히는 문장이 나와요.

---

## 🎯 작업 단계별 권장 모델 (Workflow)

| 단계 | 작업 내용 | 추천 모델 | 이유 |
| :--- | :--- | :--- | :--- |
| **1세트 초안 (톤 확립)** | 컨셉, 톤앤보이스 기준 잡기, 첫 3장 | **Opus 5 / 5.5** | 초기 뉘앙스와 브랜딩 문해력 최고 수준 확보 |
| **이후 변형 · 반복 생산** | 확정된 톤으로 4~10장 전개, 후속편 제작 | **Sonnet 5.5** | 속도·비용 효율 극대화, 예시(Few-shot)만 주면 충분 |
| **잔작업 & 미세 조정** | 해시태그 추출, 글자 수 다듬기, 줄바꿈 | **Sonnet 5.5** | 빠르고 정확한 지시 이행 |

## 💡 효과적인 요청 원칙 3가지

### 1. 제약을 숫자로 주기
* **원칙**: 어떤 thinking 설정보다 **글자 수와 줄 수 제한**이 결과를 바꿉니다.
* **예시**:
  * `"메인 카피 15자 이내로 써줘"`
  * `"서브 카피 공백 포함 35자 / 2줄 이내로 끊어줘"`
  * `"한 화면당 텍스트 3줄 초과 금지"`

### 2. 먼저 3장만 뽑아보고 톤 확인
* **원칙**: 10장 전체를 다 받고 처음부터 다시 고치는 것보다 훨씬 빠르고 정확합니다.
* **워크플로우**:
  1. 표지 + 본문 2장 (총 3장) 먼저 생성
  2. 톤앤매너, 문장 길이 확인 및 피드백
  3. 확인된 톤으로 나머지 슬라이드 요청

### 3. 좋았던 카피를 다음 요청에 붙이기 (Few-shot)
* **원칙**: 이전 작업 중 마음에 들었던 실제 예시 한두 개를 프롬프트에 넣는 것이 **모델 등급 차이보다 큽니다**.
* **예시 프롬프트 구조**:
  > "아래 톤과 길이감 그대로 유지해서 이번 주제(시간도둑 5가지)로 작성해줘."  
  > **[좋았던 레퍼런스 예시]**  
  > - 메인: No tool fits all.  
  > - 서브: 100명의 프리랜서에게는 100개의 시간 도구  
  > - 본문: 남들이 만든 시간표에 내 하루를 끼워 맞추지 마세요.

## 📋 카드뉴스 요청용 템플릿 (복사용)

```markdown
[카드뉴스 카피 작성 요청]

- 주제: (예: 뽀모도로가 나에게 안 맞는 이유)
- 타깃: 마감에 쫓기는 1인 프리랜서/창작자
- 분량: 표지 포함 총 3장 먼저 작성
- 제약 조건:
  1. 메인 헤드라인: 15자 이내 (임팩트 있는 한 문장)
  2. 서브/요약문: 2줄 이내 (각 줄 20자 내외)
  3. 설명조 잔소리 금지, '저는~' 형태의 담담한 고백/공감 톤
- 톤 레퍼런스:
  "남들이 좋다는 툴을 쓸 때마다 죄책감이 들었다면 당신 탓이 아닙니다. 도구가 내 몸에 안 맞았을 뿐입니다."
```
